LESSON 0101

Relations, keys & integrity rules

A relational database stores data in named tables. Keys identify rows; constraints keep rows valid; logical design maps the ER model into tables and references.

LESSON 0202

Relational algebra: operators & joins

Relational algebra builds a query from small table operations. Each operation produces another relation, so the operations can be combined step by step.

LESSON 0303

Relational calculus & safe queries

Relational calculus describes the condition a result row must satisfy. It says what to return, not which sequence of table operations to run.

Logical design, views & SQL schema changes

LESSON 01

Relations, keys & integrity rules

Open lesson ↗
01 Relation, tuple, attribute, and domainA relation is a set of rows with named columns. A tuple is one row, an attribute is one column, and a domain is the allowed kind of value for that column. ↗ 02 KeysA superkey is any set of attributes that uniquely identifies a row. A candidate key is a smallest such set. One candidate is chosen as the primary key. ↗ 03 Integrity constraintsAn integrity constraint is a rule every valid database state must obey. ↗ 04 Logical database design: ER model to relationsLogical database design converts a conceptual model into relation schemas with keys and constraints while keeping the real-world meaning clear. ↗
LESSON 02

Relational algebra: operators & joins

Open lesson ↗
01 Selection and projectionSelection σ keeps rows that satisfy a condition. Projection π keeps only the requested columns. ↗ 02 Set operations and joinsSet operations combine compatible relations; joins connect rows whose values satisfy a relationship condition. ↗ 03 Division: 'for every'Division returns values on one side that are paired with every required value on the other side. ↗ 04 Renaming and Cartesian productRenaming ρ gives a relation or its attributes temporary names. Cartesian product pairs every row from one relation with every row from another. ↗ 05 Relational algebra: a multi-step query exampleA relational algebra expression can combine selection, join, and projection to answer one question from several tables. ↗
LESSON 03

Relational calculus & safe queries

Open lesson ↗
01 Tuple relational calculus (TRC)TRC uses a tuple variable to describe each possible result row. Its form is { t | condition about t }. ↗ 02 Domain relational calculus (DRC)DRC uses one variable per attribute value. Its form is { <x1,…,xn> | condition about those values }. ↗ 03 Safe queriesA safe query has a finite result whose values come from the active database domain. ↗
LESSON 04

Logical design, views & SQL schema changes

Open lesson ↗
01 Ask a question with SELECTSELECT names the output columns; FROM names the input relations; WHERE filters rows. ↗ 02 Create and modify database structuresCREATE TABLE defines columns, types, keys, and constraints. ALTER TABLE changes a table's structure. ↗ 03 Views and updatabilityA view is a named SELECT statement. It is often updatable when each view row maps clearly to one base-table row. ↗ 04 Additional SQL forms (extension)These useful SQL features are not named in the official Unit 2 syllabus, so treat them as optional background after the listed topics. Triggers respond to events; embedded or dynamic SQL connects queries with programs; recursive queries follow repeated relationships. ↗ 05 Drop and alter tables and viewsALTER changes an existing database object. DROP removes an object definition; dropping a table removes its table data as well, while dropping a view removes the saved query definition. ↗
