LESSON 0101

External storage & file organization

External storage keeps records after power is off. The DBMS reads pages into memory, and a file organization determines how records are placed for searches and updates.

Index types & multilevel access

An index is a smaller guide that points toward data pages. Its layout trades extra space and update work for faster searches.

LESSON 0303

B+ trees: search, insert & range scan

A B+ tree is a balanced index whose pages guide a search to a leaf. Its linked leaves make ordered and range searches efficient.

Static & dynamic hashing

Hashing calculates a bucket from a key. Dynamic hashing splits buckets as data grows; B+ trees are often better when the query needs a range.

LESSON 01

External storage & file organization

Open lesson ↗
01 Data on external storage: pages and recordsExternal storage is persistent storage such as an SSD or hard disk. A DBMS moves data between it and memory in page-sized units, so page layout affects query cost. ↗ 02 Heap, sorted, and hashed filesA file organization decides where records are placed and how the DBMS searches for them. ↗ 03 Buffers and RAIDA buffer pool keeps frequently used pages in memory. RAID spreads or mirrors data across disks for performance or availability. ↗
LESSON 02

Index types & multilevel access

Open lesson ↗
01 What an index does and when it helpsAn index is an auxiliary structure that maps search-key values to record or page locations so a query can find selected rows without scanning every data page. ↗ 02 Dense and sparse indexesA dense index has an entry for every search-key value or record. A sparse index has fewer entries and searches within an ordered data page after locating the nearest index entry. ↗ 03 Primary, clustered, and secondary indexesA primary index is on the ordering key of an ordered data file. A clustered index follows the physical order of a non-key field. A secondary index is on a field the data file is not ordered by. ↗ 04 Multilevel indexes and ISAMA multilevel index places a small index over a larger index so each search narrows the page range. ↗
LESSON 03

B+ trees: search, insert & range scan

Open lesson ↗
01 B+ tree structureA B+ tree is a balanced, page-based search tree. Internal pages hold separator keys and child pointers; leaf pages hold data entries and are linked in key order. ↗ 02 Search and insertionSearch follows separator ranges to a leaf. Insertion places a key in that leaf and splits a full page. ↗ 03 Range queries and B-tree comparisonAfter finding the first matching leaf, a range query follows leaf links through the sorted entries. ↗
LESSON 04

Static & dynamic hashing

Open lesson ↗
01 Static hashingA hash function maps a search key to one of a fixed set of buckets. ↗ 02 Extendible hashingExtendible hashing uses a directory of hash-bit prefixes and splits a bucket when it overflows. ↗ 03 Linear hashing and range trade-offLinear hashing grows gradually using a split pointer instead of doubling a directory all at once. ↗
