LESSON 0101

Functional dependencies, closure & keys

A functional dependency is a promise about the data: once you know the values on the left, the values on the right are fixed. Closure helps test keys and consequences.

Open this lesson ↗
LESSON 0202

Schema refinement, redundancy & 1NF–3NF

Schema refinement uses keys and functional dependencies to reduce repeated facts and anomalies. Normal forms guide the design, while decomposition checks protect meaning and rules.

Open this lesson ↗
LESSON 0303

BCNF, multivalued dependencies & 4NF

BCNF checks every functional dependency: its left side must be a key. 4NF goes further and separates independent multi-valued facts.

Open this lesson ↗
LESSON 0404

Lossless & dependency-preserving decomposition

Decomposition splits one relation into smaller relations. A good split lets us join the pieces back without inventing rows and keeps important rules checkable.

LESSON 01

Functional dependencies, closure & keys

Open lesson ↗
01 Functional dependencyX → Y means that any two rows with the same X values must also have the same Y values. ↗ 02 Attribute closureX⁺ is the set of all attributes that the dependency rules can determine from X. ↗ 03 Armstrong rules and minimal coverArmstrong's reflexivity, augmentation, and transitivity rules derive dependencies that logically follow from the original rules. ↗
LESSON 02

Schema refinement, redundancy & 1NF–3NF

Open lesson ↗
01 Why redundancy causes anomaliesRedundancy is storing the same fact repeatedly. An anomaly is an error or awkwardness caused by that repetition. ↗ 02 Schema refinement in database designSchema refinement improves a table design so each fact is stored in an appropriate place and common changes do not cause anomalies. ↗ 03 First and second normal form1NF requires each cell to hold one value for its chosen domain. 2NF requires 1NF and no non-key attribute to depend on only part of a composite candidate key. ↗ 04 Third normal formA relation is in 3NF when for every nontrivial X → A, X is a superkey or A is a prime attribute (part of some candidate key). ↗
LESSON 03

BCNF, multivalued dependencies & 4NF

Open lesson ↗
01 Boyce–Codd normal form (BCNF)A relation is in BCNF if, for every nontrivial functional dependency X → Y, X is a superkey. ↗ 02 Multivalued dependencyX ↠ Y means that for one X value, the set of Y values is independent of the remaining attributes. ↗ 03 Fourth normal form (4NF)A relation is in 4NF when every nontrivial multivalued dependency has a superkey determinant. ↗
LESSON 04

Lossless & dependency-preserving decomposition

Open lesson ↗
01 Lossless-join decompositionA decomposition is lossless if joining its pieces recreates exactly the valid rows of the original relation. ↗ 02 Dependency preservationA decomposition is dependency-preserving if the rules projected onto the smaller relations still imply all the original dependencies. ↗ 03 Chase / tableau testThe chase is a table-based procedure that applies dependencies to rows of symbols to test whether a decomposition is lossless. ↗ 04 Problems caused by a poor decompositionA decomposition can be harmful if joining the pieces invents rows or if important dependencies can no longer be checked locally. ↗
