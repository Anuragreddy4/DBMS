LESSON 0101

Locks, 2PL & deadlocks

Locks control who may read or change an item at the same time. Two-phase locking gives a safe pattern; a wait-for graph helps find deadlocks.

Open this lesson ↗
LESSON 0202

Timestamp ordering & Thomas write rule

Timestamp ordering gives each transaction a place in a planned serial order. Every read or write must respect that order.

Open this lesson ↗
LESSON 0303

Validation-based concurrency control

Validation-based control lets a transaction work privately first. Just before it publishes changes, the DBMS checks whether another transaction made its work unsafe.

Open this lesson ↗
LESSON 0404

WAL, checkpoints, recovery & buffers

A log records concurrent changes. Write-ahead logging lets recovery redo committed work and undo incomplete work; checkpoints and the buffer manager help restore consistent pages.

LESSON 01

Locks, 2PL & deadlocks

Open lesson ↗
01 Shared and exclusive locksA shared (S) lock allows reading. An exclusive (X) lock allows reading and writing and must be held alone. ↗ 02 Two-phase locking2PL has a growing phase, when locks may be acquired, and a shrinking phase, when locks may be released but no new locks may be acquired. ↗ 03 DeadlockA deadlock is a cycle of transactions waiting for locks held by one another. ↗
LESSON 02

Timestamp ordering & Thomas write rule

Open lesson ↗
01 Transaction timestampsTS(T) is the unique timestamp assigned to transaction T. Smaller timestamps mean earlier in the intended serial order. ↗ 02 Read and write checksTimestamp ordering rejects an operation when allowing it would contradict the assigned transaction order. ↗ 03 Thomas's write ruleThomas's rule ignores a write that is older than the value already written, instead of aborting the whole transaction. ↗
LESSON 03

Validation-based concurrency control

Open lesson ↗
01 Read phaseThe transaction reads database values and calculates proposed changes in a private workspace. ↗ 02 Validation phaseBefore writing, the DBMS checks whether the transaction can be serialized with transactions that overlapped it. ↗ 03 Write phase and workloadIf validation succeeds, the DBMS applies the buffered writes. If it fails, the transaction aborts and may restart. ↗
LESSON 04

WAL, checkpoints, recovery & buffers

Open lesson ↗
01 Log-based recovery, atomicity, and WALA log records transaction actions so the DBMS can recover after a failure. WAL requires the log record to reach stable storage before the changed data page is written. ↗ 02 Checkpoint and ARIESA checkpoint records recovery information so restart can begin near recent work. ARIES recovers in Analysis, Redo, and Undo phases. ↗ 03 Buffer managerThe buffer manager keeps disk pages in memory while queries use them. ↗ 04 Recovery with concurrent transactionsConcurrent recovery tracks several transactions whose log records may be interleaved, then restores committed work and removes incomplete work after a crash. ↗
