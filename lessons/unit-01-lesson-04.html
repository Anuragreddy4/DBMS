UNIT 01 · LESSON 04

ER design, EER features & mapping

IN PLAIN WORDS

An ER design starts from requirements and names the entities, attributes, relationships, keys, and constraints the database must preserve.

By the end, you can:
  • Identify entity sets, attributes, keys, and relationship sets
  • Specify cardinality and participation constraints
  • Use extended ER features and map a design into relations

EXPLANATION
TOPIC 01

Entities, entity sets, attributes, and keys

DEFINITION

An entity is one identifiable thing about which data is stored. An entity set is the collection of similar entities. Attributes describe each entity, and a key identifies it uniquely.

A STUDENT entity set contains individual students. sid can identify one student; name and program describe that student. A value such as Mina is an attribute value, not an entity set.

Attributes may be simple, composite, single-valued, multivalued, or derived. A weak entity cannot be identified by its own attributes alone; it uses an owner key together with a partial key.

In a common ER diagram, an entity set is a rectangle, an attribute an oval, and a key attribute is marked. A weak entity has a distinct double-rectangle notation.

QUICK EXAMPLE

STUDENT(sid,name,birthDate) is an entity set. A row with sid=21 represents one entity. Age can be derived from birthDate; a student may have several phone numbers, so phone is multivalued.

TOPIC 02

Relationships and relationship sets

DEFINITION

A relationship is an association among particular entities. A relationship set is the collection of associations of the same kind.

ENROLLS is a relationship set between STUDENT and COURSE. One enrollment instance connects one particular student with one particular course.

Cardinality says how many entities may be associated: 1:1, 1:N, or M:N. The degree counts participating entity sets; a relationship involving three sets is ternary.

Participation says whether an entity must take part. Total participation means every entity does; partial participation allows an entity to have no relationship. These rules express real constraints.

QUICK EXAMPLE

A student can enroll in many courses and each course can have many students, so STUDENT–ENROLLS–COURSE is M:N. A student who has not enrolled yet can still exist, so student participation may be partial.

TOPIC 03

Additional ER features and mapping beyond ER

DEFINITION

The extended ER model adds ways to describe subtypes, shared properties, and more complex constraints. Mapping then turns the conceptual ER design into relational tables.

Specialization divides a superclass into subtypes; generalization combines similar entity sets into a superclass. Subtypes inherit common attributes and relationships.

A specialization can be disjoint or overlapping. Disjoint means an entity belongs to at most one subtype; overlapping allows several. Total (covering) means every superclass entity belongs to a subtype; partial allows some to belong to none.

Aggregation treats a relationship as a higher-level unit so it can take part in another relationship. A weak entity depends on an owner and a partial key. An associative entity gives an M:N relationship its own attributes and identity.

When mapping to relations, make a table for each entity set, put a foreign key on the many side of a 1:N relationship, and create a bridge table for an M:N relationship. Preserve keys and constraints.

QUICK EXAMPLE

PERSON may be specialized into STUDENT and EMPLOYEE. A person may be both, so the specialization overlaps. ENROLLS between STUDENT and COURSE becomes ENROLLMENT(sid,cid,term,grade); term and grade describe the relationship.

TOPIC 04

Conceptual database design with ER diagrams

DEFINITION

Conceptual design turns written requirements into a clear, technology-independent picture of the data and the rules connecting it.

Read the requirements and list entity sets, attributes, and candidate keys. Then identify relationship sets, degree, cardinality, and participation constraints.

Check weak entities, multivalued attributes, and subtypes. Draw the ER diagram and review it against example questions the database must answer.

After the ER design is clear, map it to relations and choose physical storage. The ER diagram describes meaning; it is not a disk layout.

QUICK EXAMPLE

For a library, identify MEMBER, BOOK, and LOAN. A loan connects one member and one book and stores checkoutDate and dueDate. Decide whether a member can have zero loans, whether a book can have many loans over time, and which values identify each entity.

TOPIC 05

Associative entity

DEFINITION

An associative entity turns a relationship, usually M:N, into an entity that can carry its own attributes.

Build it from the participating entity keys and add facts that describe the association.

It is useful when the relationship has a date, status, grade, quantity, or separate lifecycle.

QUICK EXAMPLE

ENROLLMENT(sid,cid,term,grade) represents one student taking one course in one term; grade belongs to that enrollment, not to the student or course alone.

TOPIC 06

Ternary relationship

DEFINITION

A ternary relationship connects three entity sets in one relationship instance.

Its meaning belongs to the complete triple. Replacing it with three binary relationships can allow combinations that were never valid.

The degree of a relationship is the number of participating entity sets; ternary means degree three.

QUICK EXAMPLE

SUPPLIES(supplier,part,project) records which supplier provides which part for which project. The fact is about that exact three-way combination.

TOPIC 07

EER overlap and covering constraints

DEFINITION

Overlap and covering state which subtype memberships are allowed and whether every superclass entity must appear in a subtype.

Disjoint subtypes allow at most one subtype membership; overlapping subtypes allow more than one.

Total specialization requires every superclass entity to appear in some subtype. Partial specialization allows entities in none.

QUICK EXAMPLE

A PERSON can be both STUDENT and EMPLOYEE, so the subtypes overlap. If every person must be one of those, the specialization is total; otherwise it is partial.

WORKED EXAMPLE · SELECT A STEP

Turn course registration into tables

A college records which students take which courses, and the grade each student gets.

TableExample rowWhat it means
STUDENT1, AshaOne student
COURSEC1, DBMSOne course
ENROLLMENT1, C1, Spring, AAsha takes DBMS in Spring and gets A
STEP 01

List the things

Students and courses are two kinds of things the college wants to store. Each gets its own table.

STEP 02

Connect the things

A student can take many courses, and a course can have many students. ENROLLMENT records each connection.

STEP 03

Store details with the connection

The term and grade belong to one student's course registration, so they go in ENROLLMENT.

RESULT

Use one STUDENT table, one COURSE table, and one ENROLLMENT table to record each registration.

EXAM FOCUS

What to be ready to explain

Design an ER model for a hospital, library, course registration, or reservation system. State assumptions, keys, cardinality, participation, weak entities, and EER features.
