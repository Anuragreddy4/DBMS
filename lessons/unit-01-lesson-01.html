UNIT 01 · LESSON 01

Database System vs. File System

IN PLAIN WORDS

A database stores organized facts. A DBMS manages those facts, and a database system includes the data and the programs that use it. Comparing a DBMS with separate application files shows why shared rules matter.

By the end, you can:
  • Distinguish a database, a DBMS, and a database system
  • Compare a traditional file-processing system with a DBMS
  • Trace a request from an application to stored data and back

EXPLANATION
TOPIC 01

Database, DBMS, and database system

DEFINITION

A database is an organized collection of related data. A DBMS (database management system) is the software that defines the data structure, stores and retrieves the data, applies rules, and controls access. A database system means the data together with the programs used to access and modify it.

Keep the parts separate: STUDENT(sid, name, course) describes a table; rows such as (21, Mina, DBMS) are stored data; the DBMS is the software that manages the table and its rows. The table description is the schema, while its current rows are the data instance.

When an app asks for the course where sid=21, the request goes to the DBMS. The DBMS checks the request and the user's permission, locates the matching row, and returns the requested value. The app does not need to know how the DBMS stores that row on disk.

The DBMS helps people use related data conveniently and efficiently. It can enforce data rules, manage access, coordinate users, and support recovery if a failure interrupts work.

QUICK EXAMPLE

In STUDENT(sid, name, course), the row (21, Mina, DBMS) is data. The DBMS is the software that can create this table, check its rules, find the row, and return the course. It is not the row itself.

TOPIC 02

Database System vs. File System

DEFINITION

In a traditional file-processing system, each application keeps and understands its own files. A DBMS manages a shared, described database and controls how applications read and change it.

ConcernTraditional file-processing systemDatabase system with a DBMS
OrganizationPrograms maintain separate files and often know their formats.A shared database has a defined schema and catalog.
Repeated factsCopies can multiply and disagree after an incomplete update.Shared tables and good design reduce repetition; constraints help protect consistency.
Program changesA file-format change may require edits to every program that reads it.The DBMS separates logical requests from many storage details.
Rules and accessEach application may need to repeat validation and access checks.Constraints and permissions can be managed centrally.
Concurrent workPrograms must coordinate simultaneous reads and writes themselves.Transactions and concurrency control coordinate users.
Failure recoveryRecovery is often designed separately for each application.Logs and recovery procedures help undo incomplete work and restore committed work.
Best fitSimple, isolated data with low coordination needs.Shared, related data with multiple users or important integrity requirements.

Separate files can repeat the same fact. If a student address is copied into fees.csv, library.csv, and hostel.csv, changing only two copies leaves conflicting addresses. This is an update anomaly.

A DBMS lets several applications use one agreed structure. Keys and constraints check the data; transactions coordinate simultaneous changes; authorization and recovery are managed by the database system.

A DBMS has setup, storage, and administration costs. A small, isolated file can be simpler. The advantage appears when data is shared, related, frequently updated, or important to protect.

QUICK EXAMPLE

Suppose the fees and library programs each keep a student name and address. If a student moves, one program may update its file while the other does not. With a shared STUDENT row in a DBMS, both programs read the same current address and the DBMS can check who is allowed to change it.

WORKED EXAMPLE · SELECT A STEP

Find a student's course

A class app asks: “Which course is student 1 taking?” The table has two students.

Student IDNameCourse
1AshaDBMS
2RaviOS
STEP 01

The app asks

The app sends the DBMS a simple request: find the course for student ID 1.

STEP 02

The DBMS looks

The DBMS checks the STUDENT table and finds the row whose ID is 1.

STEP 03

The answer comes back

That row says Asha is taking DBMS, so the app receives “DBMS”.

RESULT

The app asks a question, the DBMS finds the matching row, and the database supplies the answer: DBMS.

What to be ready to explain

Be ready to compare file processing and DBMS by redundancy, inconsistency, integrity, concurrent access, security, recovery, and cost.
