UNIT 02 · LESSON 03

Relational calculus & safe queries

IN PLAIN WORDS

Relational calculus describes the condition a result row must satisfy. It says what to return, not which sequence of table operations to run.

By the end, you can:
  • Tell tuple calculus from domain calculus
  • Read predicates and quantifiers
  • Explain why unsafe queries must be restricted
TOPICS IN THIS LESSON

EXPLANATION
TOPIC 01

Tuple relational calculus (TRC)

DEFINITION

TRC uses a tuple variable to describe each possible result row. Its form is { t | condition about t }.

The condition can refer to tuples in relations and compare their attributes.

A tuple variable ranges over possible tuples, so a safe query must restrict it to values grounded in the database.

QUICK EXAMPLE

{s.name | STUDENT(s) and s.program='CS'} describes the names of students whose program is CS.

TOPIC 02

Domain relational calculus (DRC)

DEFINITION

DRC uses one variable per attribute value. Its form is { <x1,…,xn> | condition about those values }.

TRC ranges over whole tuples; DRC ranges over the values in the tuple's columns.

Both use logic such as AND, OR, NOT, and exists. An 'all' condition can be written as 'there is no required item missing'.

QUICK EXAMPLE

A DRC query can return <n> when some <id,n,p> is a STUDENT row and p='CS'.

TOPIC 03

Safe queries

DEFINITION

A safe query has a finite result whose values come from the active database domain.

A query that asks for every value that is not in a relation could range over all possible strings or numbers, producing an unbounded answer.

Make the query safe by anchoring variables to rows or values that occur in the database, then apply the negative condition.

QUICK EXAMPLE

Instead of listing all possible people who are not students, start with the finite PERSON relation and return its rows for which no STUDENT row exists.

WORKED EXAMPLE · SELECT A STEP

Find students enrolled in DBMS

STUDENT has Asha (ID 1) and Bilal (ID 2). ENROLLMENT says ID 1 takes DBMS and ID 2 takes OS.

STEP 01

Start with real students

Check the students that actually appear in the STUDENT table.

STEP 02

Look for a matching registration

For each student, check ENROLLMENT for the same ID and the course DBMS.

STEP 03

Return the matching name

ID 1 has a DBMS registration, so the answer is Asha. ID 2 does not match.

RESULT

Tuple calculus describes which student rows should be returned. Domain calculus describes which individual column values should be returned. Both express the same request: Asha.
