UNIT 06 · LESSON 01

External storage & file organization

IN PLAIN WORDS

External storage keeps records after power is off. The DBMS reads pages into memory, and a file organization determines how records are placed for searches and updates.

By the end, you can:
  • Explain pages, records, and I/O on external storage
  • Compare heap, sorted, and hashed file organizations
  • Choose a layout for equality lookups, ranges, and scans
TOPICS IN THIS LESSON

EXPLANATION
TOPIC 01

Data on external storage: pages and records

DEFINITION

External storage is persistent storage such as an SSD or hard disk. A DBMS moves data between it and memory in page-sized units, so page layout affects query cost.

A page (or block) groups records and metadata. The DBMS usually reads or writes a whole page even when a query needs one small value.

A slotted page uses a slot directory to locate records. With variable-length records, record bytes can move inside the page while a slot number remains the reference.

Sequential scans read many pages in order; an index can reduce reads for selective lookups. If a query needs most rows, scanning the pages may be cheaper than following many index pointers.

QUICK EXAMPLE

A search for one student among 1,000 pages may read many pages without an index. An index can point to the relevant page. A report that needs nearly every student may be faster as a full scan.

TOPIC 02

Heap, sorted, and hashed files

DEFINITION

A file organization decides where records are placed and how the DBMS searches for them.

Heap: place new records wherever space is available; insertion is simple, search may scan. Sorted: keep records ordered by a key; range queries are useful, insertion can be expensive.

Hash: compute a bucket from a key; equality search is fast, but the file is not ordered for ranges. Collisions may use overflow pages.

QUICK EXAMPLE

Choose hashing for many equality lookups by student id; choose sorted data or a B+ tree for listing ids between two values.

TOPIC 03

Buffers and RAID

DEFINITION

A buffer pool keeps frequently used pages in memory. RAID spreads or mirrors data across disks for performance or availability.

The buffer manager pins pages in use, marks changed pages dirty, and later flushes them to disk. LRU and clock can choose an unpinned page to replace.

RAID can use striping to distribute blocks or mirroring to keep copies. RAID does not replace database backups.

QUICK EXAMPLE

If several queries reuse a page already in the buffer, the DBMS may avoid another disk read.

WORKED EXAMPLE · SELECT A STEP

Choose a file layout for common tasks

A school often adds student records, looks up one student by ID, and prints a range of IDs.

LayoutSimple benefitSimple drawback
HeapEasy to add a new recordMay scan many rows to find one ID
SortedEasy to list IDs in orderAdding a row may require moving records
HashFast to find an exact IDNot good for ID ranges
STEP 01

Think about new records

If the school mostly adds records, a heap file is simple because a new row can go in the next open space.

STEP 02

Think about an exact ID

Hashing can jump to the place for one exact ID instead of checking every row.

STEP 03

Think about a range

Sorted records make it easier to find IDs from 100 to 120 because nearby IDs are stored together.

RESULT

Choose the layout that matches the most common task. No one layout is best for every kind of search.

EXAM FOCUS

What to be ready to explain

Explain external storage and pages, compare heap/sorted/hash file organizations, describe a slotted page, and choose a layout for a workload.
