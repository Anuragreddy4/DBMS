UNIT 05 · LESSON 03

Validation-based concurrency control

IN PLAIN WORDS

Validation-based control lets a transaction work privately first. Just before it publishes changes, the DBMS checks whether another transaction made its work unsafe.

By the end, you can:
  • Name the read, validation, and write phases
  • Explain what validation checks
  • Choose when optimistic control is useful
TOPICS IN THIS LESSON
01Read phase↘02Validation phase↘03Write phase and workload↘
EXPLANATION
TOPIC 01

Read phase

DEFINITION

The transaction reads database values and calculates proposed changes in a private workspace.

It records the items it read and the items it plans to write.

Other transactions are not blocked by locks held for this private work.

QUICK EXAMPLE

A seat-booking transaction reads the available-seat count and prepares a new enrollment without publishing it yet.

TOPIC 02

Validation phase

DEFINITION

Before writing, the DBMS checks whether the transaction can be serialized with transactions that overlapped it.

Validation compares read sets and write sets and considers which transactions started, validated, and wrote first.

If another committed transaction changed information this transaction relied on, validation rejects it so it can retry with fresh data.

QUICK EXAMPLE

Two transactions both read that one seat is free. The second cannot publish its enrollment using that now-stale count.

TOPIC 03

Write phase and workload

DEFINITION

If validation succeeds, the DBMS applies the buffered writes. If it fails, the transaction aborts and may restart.

This approach works well when conflicts are rare because transactions can read without waiting for locks.

Under high contention, repeated failed validations waste work. Range or predicate locking may be needed to prevent a phantom row from changing a query's result set.

QUICK EXAMPLE

Read-heavy reports may benefit; a hot inventory counter may cause many retries.

WORKED EXAMPLE · SELECT A STEP

Protect the last seat with validation

One seat is left. Two students begin booking at the same time. They first work without locking the seat.

BookingWhat it sawValidation result
T11 seat leftPasses first and books it
T21 seat leftFails because T1 has already booked it
STEP 01

Both check the seat

T1 and T2 each see one seat left and prepare a booking.

STEP 02

Check T1 before saving

T1 validates first. The seat count has not changed, so T1's booking is accepted.

STEP 03

Check T2 before saving

T2 now validates. The seat count changed after T2 read it, so T2 must try again and cannot take the last seat.

RESULT

Validation catches the conflict before both bookings are saved. Only one student gets the last seat.

EXAM FOCUS

What to be ready to explain

Describe the read, validation, and write phases. Compare validation-based, lock-based, and timestamp-based control for different workloads.
