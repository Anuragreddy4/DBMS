UNIT 06 · LESSON 04

Static & dynamic hashing

IN PLAIN WORDS

Hashing calculates a bucket from a key. Dynamic hashing splits buckets as data grows; B+ trees are often better when the query needs a range.

By the end, you can:
  • Explain collisions and overflow pages
  • Trace extendible hashing depth and splits
  • Compare hashing with tree indexes
TOPICS IN THIS LESSON

EXPLANATION
TOPIC 01

Static hashing

DEFINITION

A hash function maps a search key to one of a fixed set of buckets.

Different keys can map to the same bucket; this is a collision. Overflow pages store records when the main bucket fills.

As a file grows, long overflow chains and skewed buckets can make search slower.

QUICK EXAMPLE

With h(sid)=sid mod 4, ids 12 and 20 both map to bucket 0.

TOPIC 02

Extendible hashing

DEFINITION

Extendible hashing uses a directory of hash-bit prefixes and splits a bucket when it overflows.

Global depth is the number of hash bits used by the directory. Local depth says how many bits distinguish one bucket.

If a split needs more bits than the directory currently uses, double the directory. Only the overflowing bucket's records are redistributed.

QUICK EXAMPLE

A bucket with local depth 1 splits using the next hash bit. If that raises local depth beyond global depth, double the directory.

TOPIC 03

Linear hashing and range trade-off

DEFINITION

Linear hashing grows gradually using a split pointer instead of doubling a directory all at once.

Both extendible and linear hashing adapt buckets as data grows, but they organize splits differently.

Hashing is designed for equality tests. Because bucket order is unrelated to key order, a range query usually cannot follow adjacent values. A B+ tree preserves that order.

QUICK EXAMPLE

Find sid=140: a hash index can jump to its bucket. Find all ids from 100 through 160: a B+ tree can move through adjacent leaves.

WORKED EXAMPLE · SELECT A STEP

Split one full hash bucket

A hash directory checks the last 1 bit of a key. The bucket for keys ending in 0 is full, so it must split.

Key's last 2 bitsNew bucket
00Bucket 00
10Bucket 10
STEP 01

Look at the full bucket

The directory currently checks only one bit, so both 00 and 10 go to the bucket ending in 0.

STEP 02

Split that bucket

Make two smaller buckets. Check two bits now: keys ending in 00 go to one, and keys ending in 10 go to the other.

STEP 03

Make the directory bigger

The directory needs two bits to point to the new buckets, so it doubles from two entries to four.

RESULT

Extendible hashing splits only the full bucket. If the directory needs another bit to tell the buckets apart, it doubles.

EXAM FOCUS

What to be ready to explain

Compare static, extendible, and linear hashing. Trace overflow/split and compare hash-based with tree-based indexing for point and range queries.
