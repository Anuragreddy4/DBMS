UNIT 01 · LESSON 03

Models, schema, instance & languages

IN PLAIN WORDS

A data model is a way to describe data. A schema is the plan; an instance is today's contents. SQL provides commands to define, query, and change the database.

By the end, you can:
  • Compare a schema with an instance
  • Recognize common data models
  • Classify SQL commands and explain views
TOPICS IN THIS LESSON

EXPLANATION
TOPIC 01

Data models

DEFINITION

A data model is a set of ideas for describing data, its relationships, and its rules.

The relational model organizes data in tables. Hierarchical and network models use parent-child or linked records. Object-based models represent richer objects.

A model helps designers express what must be stored before choosing physical storage.

QUICK EXAMPLE

A college can be represented relationally using STUDENT, COURSE, and ENROLLMENT tables.

TOPIC 02

Schema and instance

DEFINITION

The schema is the database's structure. The instance is the actual data present at a particular time.

The schema changes occasionally; the instance changes whenever records are inserted, updated, or deleted.

A DBMS checks that each instance follows the schema's types, keys, and constraints.

QUICK EXAMPLE

STUDENT(sid, name, program) is a schema. Rows for Anu and Dev are part of one current instance.

TOPIC 03

Database languages

DEFINITION

DDL defines structures; DML reads or changes rows; DCL controls privileges; TCL commits or rolls back transactions.

SQL combines these command families. CREATE and ALTER are DDL; SELECT, INSERT, UPDATE, and DELETE are DML; GRANT and REVOKE are DCL; COMMIT and ROLLBACK are TCL.

QUICK EXAMPLE

CREATE TABLE defines a relation. SELECT retrieves rows. COMMIT makes a transaction's changes final.

TOPIC 04

Views

DEFINITION

A view is a named query that users can read like a table. It can simplify queries and show only selected rows or columns.

A regular view stores its query definition. A materialized view stores a result that the DBMS refreshes.

A view can restrict exposure, but it does not replace the need for correct authorization on the underlying data.

QUICK EXAMPLE

A CS_Students view can show student IDs and names only for the CS program.

WORKED EXAMPLE · SELECT A STEP

Tell the plan from the current data

Use the schema STUDENT(sid, name, program). The current rows are (21, Mina, CS) and (22, Arjun, IT).

CREATE VIEW CS_Students AS
SELECT sid, name
FROM STUDENT
WHERE program = 'CS';
STEP 01

Identify the schema

The names sid, name, and program describe the columns and their meaning. That design is the schema.

STEP 02

Identify the instance

The two student rows are the instance right now. Adding a third student changes the instance, not the schema.

STEP 03

Create a view

A query can expose just CS students: CREATE VIEW CS_Students AS SELECT sid, name FROM STUDENT WHERE program='CS'. The view hides the program filter from repeated queries.

RESULT

The table definition is the schema, the rows are the instance, and CS_Students is a view over those rows.

EXAM FOCUS

What to be ready to explain

Define schema and instance; list data models and database languages; explain a view and its purpose.
