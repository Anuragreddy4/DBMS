UNIT 05 · LESSON 02

Timestamp ordering & Thomas write rule

IN PLAIN WORDS

Timestamp ordering gives each transaction a place in a planned serial order. Every read or write must respect that order.

By the end, you can:
  • Define transaction and item timestamps
  • Apply readTS and writeTS checks
  • Explain Thomas's write rule
TOPICS IN THIS LESSON
01Transaction timestamps↘02Read and write checks↘03Thomas's write rule↘
EXPLANATION
TOPIC 01

Transaction timestamps

DEFINITION

TS(T) is the unique timestamp assigned to transaction T. Smaller timestamps mean earlier in the intended serial order.

For each item Q, readTS(Q) stores the largest timestamp of any transaction that successfully read Q.

writeTS(Q) stores the largest timestamp of any transaction that successfully wrote Q.

QUICK EXAMPLE

If readTS(Q)=25, the item has already been read by a transaction whose timestamp is 25.

TOPIC 02

Read and write checks

DEFINITION

Timestamp ordering rejects an operation when allowing it would contradict the assigned transaction order.

A read by T is rejected if TS(T)<writeTS(Q): an earlier transaction is trying to read before a newer value that already exists.

For write(Q), abort T if TS(T)<readTS(Q). If TS(T)<writeTS(Q), the write is obsolete; basic ordering aborts it, while Thomas's rule ignores it. Otherwise, perform the write and update writeTS(Q).

QUICK EXAMPLE

An older transaction cannot overwrite a value after a newer transaction has already read it.

TOPIC 03

Thomas's write rule

DEFINITION

Thomas's rule ignores a write that is older than the value already written, instead of aborting the whole transaction.

The newer write already makes the old value irrelevant to the final database state.

It permits some schedules that basic timestamp ordering rejects, while keeping the valid timestamp order.

QUICK EXAMPLE

If TS(T)=10 but writeTS(Q)=20, T's write is obsolete; ignore that write rather than replace Q with older data.

WORKED EXAMPLE · SELECT A STEP

Check operations on item Q

Let TS(T1)=10, TS(T2)=20, and TS(T3)=30. Initially readTS(Q)=0 and writeTS(Q)=0.

OperationCheckOutcome
T2: write(Q)20 ≥ 0Accept; writeTS=20
T1: read(Q)10 < writeTS 20Abort
T1: write(Q)10 < writeTS 20Abort or ignore by Thomas
STEP 01

T2 writes Q

20 is not less than readTS(Q)=0 or writeTS(Q)=0. Accept the write and set writeTS(Q)=20.

STEP 02

T1 tries to read Q

TS(T1)=10 is less than writeTS(Q)=20. Abort T1's read: it is too old to see a value written by a later transaction.

STEP 03

T1 tries an old write instead

Because 10 is less than writeTS(Q)=20, basic timestamp ordering aborts it. Thomas's rule may ignore the obsolete write.

RESULT

Use readTS to protect earlier readers and writeTS to protect the order of writes. State clearly whether the Thomas rule is being applied.

EXAM FOCUS

What to be ready to explain

Explain timestamp ordering using readTS and writeTS, then demonstrate Thomas's write rule on a schedule.
