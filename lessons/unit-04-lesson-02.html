UNIT 04 · LESSON 02

Schedules, concurrency & conflicts

IN PLAIN WORDS

A schedule is the order in which transactions' reads and writes happen. Interleaving can save time, but conflicting operations need a safe order.

By the end, you can:
  • Read a schedule while preserving transaction order
  • Identify read-write, write-read, and write-write conflicts
  • Explain why concurrent execution needs control
TOPICS IN THIS LESSON

EXPLANATION
TOPIC 01

Serial and concurrent schedules

DEFINITION

A schedule lists operations from one or more transactions. A serial schedule runs one whole transaction before another; a concurrent schedule interleaves their operations.

A valid schedule preserves the original order of operations within each transaction.

Interleaving can keep CPU and storage busy while another transaction waits, improving throughput.

QUICK EXAMPLE

T1: read A, write A. T2: read B, write B. A schedule may interleave those steps because the transactions use different data.

TOPIC 02

When do operations conflict?

DEFINITION

Two operations conflict if they are from different transactions, access the same item, and at least one is a write.

Read-read is not a conflict. Read-write, write-read, and write-write on the same item are conflicts.

The order of a conflicting pair can affect the result, so a scheduler must preserve a correct serial order.

QUICK EXAMPLE

If T1 and T2 both write balance A, changing which write occurs last can change the final balance.

TOPIC 03

Problems caused by uncontrolled overlap

DEFINITION

Concurrency anomalies are incorrect results caused by unsafe interleaving.

A lost update occurs when one write overwrites another. A dirty read uses a value that may later be rolled back. An unrepeatable read gets different values on two reads in one transaction.

Concurrency-control protocols prevent or manage these effects.

QUICK EXAMPLE

Two people each see one available seat and both enroll a student. Without coordination, the database may accept two students for the last seat.

WORKED EXAMPLE · SELECT A STEP

See how one update can be lost

There are 2 seats left. Two students try to reserve one seat at almost the same time.

What happensSeats left
Both students read the starting value2
Student A calculates a new value1
Student B calculates from the same old value1

STEP 01

Both see the same number

Each booking reads 2 seats before either booking saves its change.

STEP 02

Both calculate one seat left

Each subtracts one from 2, so each prepares to write 1.

STEP 03

One booking overwrites the other

The final value is 1, even though two seats were booked. One update disappeared: a lost update.

RESULT

The correct value is 0 seats. The DBMS must coordinate the two bookings so one cannot overwrite the other's change.

EXAM FOCUS

What to be ready to explain

Define serial and concurrent schedules. Identify conflicting operation pairs and explain the motivation for concurrency control.
