UNIT 02 · LESSON 02

Relational algebra: operators & joins

IN PLAIN WORDS

Relational algebra builds a query from small table operations. Each operation produces another relation, so the operations can be combined step by step.

By the end, you can:
  • Apply selection, projection, and renaming
  • Use set operations, products, joins, and division
  • Write a multi-step algebra expression and explain intermediate results
TOPICS IN THIS LESSON

EXPLANATION
TOPIC 01

Selection and projection

DEFINITION

Selection σ keeps rows that satisfy a condition. Projection π keeps only the requested columns.

Selection σ keeps complete rows that satisfy a condition. Projection π keeps the requested columns; under the relational model it removes duplicate result tuples.

Use selection to answer “which rows?” and projection to answer “which attributes?” Combine them when a question asks for a few columns from matching rows.

QUICK EXAMPLE

σprogram='CS'(STUDENT) keeps CS students. πname(σprogram='CS'(STUDENT)) returns just their names.

TOPIC 02

Set operations and joins

DEFINITION

Set operations combine compatible relations; joins connect rows whose values satisfy a relationship condition.

Union R ∪ S returns rows in either relation; intersection R ∩ S returns rows in both; difference R − S returns rows in R but not S. These operations require union-compatible relations.

A theta join uses a comparison condition; an equijoin uses equality; a natural join matches same-named attributes and keeps one copy of the join column.

A Cartesian product pairs every row of one relation with every row of another. A join can be understood as a product followed by a selection.

QUICK EXAMPLE

If CS_STUDENT and DBMS_STUDENT have compatible columns, their intersection returns students in both sets. Joining ENROLLMENT with COURSE on cid adds the course title to each registration.

TOPIC 03

Division: 'for every'

DEFINITION

Division returns values on one side that are paired with every required value on the other side.

It is useful when the question contains words such as 'all required courses' or 'every project part'.

To use it, compare the pairs a person has with the complete set they must have.

QUICK EXAMPLE

ENROLLMENT(sid,cid) ÷ REQUIRED(cid) returns students enrolled in every required course.

TOPIC 04

Renaming and Cartesian product

DEFINITION

Renaming ρ gives a relation or its attributes temporary names. Cartesian product pairs every row from one relation with every row from another.

Renaming is especially useful when the same relation is used twice, such as comparing two employees in EMPLOYEE.

A product of relations with m and n rows has m×n row pairs before a condition filters it. Products can become large, so a join condition is normally applied.

QUICK EXAMPLE

Rename EMPLOYEE as E1 and E2. A condition E1.managerId=E2.empId can compare an employee with a manager stored in the same relation.

TOPIC 05

Relational algebra: a multi-step query example

DEFINITION

A relational algebra expression can combine selection, join, and projection to answer one question from several tables.

Translate the question into three decisions: which rows qualify, which relations must be connected, and which columns belong in the answer.

Apply selective conditions early when possible. Each intermediate result is a relation and becomes the input to the next operation.

QUICK EXAMPLE

Question: list names of CS students enrolled in DBMS. Select CS students and the DBMS course, join those results with ENROLLMENT on sid and cid, then project the student name: πname(σprogram='CS' and title='DBMS'(STUDENT ⋈ ENROLLMENT ⋈ COURSE)).

WORKED EXAMPLE · SELECT A STEP

Keep CS students, then show only their names

The table has three students. We want the names of the students in CS.

The answer is Asha and Chen. In relational algebra, selection chooses rows and projection chooses columns.

EXAM FOCUS

What to be ready to explain

Write relational-algebra expressions for selection, projection, set operations, joins, and division. Show the intermediate relation for each step.
