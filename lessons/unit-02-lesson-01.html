UNIT 02 · LESSON 01

Relations, keys & integrity rules

IN PLAIN WORDS

A relational database stores data in named tables. Keys identify rows; constraints keep rows valid; logical design maps the ER model into tables and references.

By the end, you can:
  • Explain relation, tuple, attribute, domain, degree, and cardinality
  • Find candidate, primary, and foreign keys
  • Apply integrity rules to a small database
TOPICS IN THIS LESSON

EXPLANATION
TOPIC 01

Relation, tuple, attribute, and domain

DEFINITION

A relation is a set of rows with named columns. A tuple is one row, an attribute is one column, and a domain is the allowed kind of value for that column.

Degree (or arity) counts the attributes. Cardinality counts the tuples currently in the relation.

In the mathematical model, a relation has no duplicate tuples and no meaningful row order. A table display may show an order, but a query needs ORDER BY to request one.

QUICK EXAMPLE

STUDENT(sid, name, program) has degree 3. If it currently has 40 students, its cardinality is 40.

TOPIC 02

Keys

DEFINITION

A superkey is any set of attributes that uniquely identifies a row. A candidate key is a smallest such set. One candidate is chosen as the primary key.

A table may have several candidate keys. A composite key contains more than one attribute.

A foreign key in one table points to a key in another table, linking the rows.

QUICK EXAMPLE

In ENROLLMENT(sid,cid,term,grade), (sid,cid,term) may be the key if a student can take the same course in different terms.

TOPIC 03

Integrity constraints

DEFINITION

An integrity constraint is a rule every valid database state must obey.

A domain rule restricts a value's type or range. A key rule prevents duplicate identifiers. Entity integrity says no part of the primary key can be NULL.

Referential integrity says a non-NULL foreign-key value must match an existing referenced key. This prevents orphan rows.

QUICK EXAMPLE

If ENROLLMENT.sid refers to STUDENT.sid, a registration for sid=999 is rejected when no student 999 exists.

TOPIC 04

Logical database design: ER model to relations

DEFINITION

Logical database design converts a conceptual model into relation schemas with keys and constraints while keeping the real-world meaning clear.

Create a relation for each strong entity set and choose its primary key. Include useful components of composite attributes as columns.

For a 1:N relationship, place the key from the one side as a foreign key on the many side. For an M:N relationship, create a bridge relation containing both keys and any relationship attributes.

Represent a weak entity with the owner key plus its partial key. Check that foreign keys and uniqueness rules preserve the original ER constraints.

QUICK EXAMPLE

Map STUDENT–ENROLLS–COURSE to STUDENT(sid,name), COURSE(cid,title), and ENROLLMENT(sid,cid,term,grade). ENROLLMENT has foreign keys to both parent tables and a key such as (sid,cid,term).

WORKED EXAMPLE · SELECT A STEP

Check whether a registration row is allowed

Student IDs 1 and 2 exist. Course DBMS exists. A registration must use a real student, a real course, and a unique student-course pair.

Student IDCourseGradeResult
1DBMSAAllowed
9DBMSARejected: student 9 is missing
1DBMSBRejected: same student-course pair
STEP 01

Check the values

The ID must be a student number, the course must be a known course, and the grade must be an allowed grade.

STEP 02

Check for a duplicate

Student 1 can have only one DBMS registration row for this term. A second row for the same pair is not allowed.

STEP 03

Check the linked records

Student 9 is not in STUDENT, so a DBMS registration for student 9 must be rejected.

RESULT

A valid row uses allowed values, does not repeat its key, and points to student and course rows that really exist.

EXAM FOCUS

What to be ready to explain

Define relation, tuple, degree, and cardinality. Explain primary and foreign keys and show domain, key, entity, and referential constraints with examples.
