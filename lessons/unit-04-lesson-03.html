UNIT 04 · LESSON 03

Conflict & view serializability

IN PLAIN WORDS

Serializability asks whether an interleaved schedule gives the same result as some safe serial order. A precedence graph turns that question into a cycle check.

By the end, you can:
  • Build a precedence graph from conflicting operations
  • Test for a cycle and read a serial order from an acyclic graph
  • Distinguish conflict serializability from view serializability

EXPLANATION
TOPIC 01

Conflict serializability

DEFINITION

A schedule is conflict-serializable if swapping adjacent non-conflicting operations can turn it into a serial schedule.

Create one graph node for each transaction. For each conflict on the same item, draw an arrow from the transaction with the earlier operation to the one with the later operation.

If the graph has no directed cycle, the schedule is conflict-serializable. A topological ordering gives an equivalent serial order.

QUICK EXAMPLE

T1 writes A before T2 reads A, so draw T1→T2.

TOPIC 02

Cycles in the precedence graph

DEFINITION

A directed cycle means the transactions require contradictory orders, so the schedule is not conflict-serializable.

One edge T1→T2 says T1 must come before T2. A reverse edge T2→T1 says the opposite.

The cycle test applies to conflict serializability, not every other notion of equivalence.

QUICK EXAMPLE

T1→T2 and T2→T1 form a cycle, so no serial order can satisfy both.

TOPIC 03

View serializability

DEFINITION

View equivalence preserves which transaction each read gets its value from and which transaction performs the final write.

View serializability includes every conflict-serializable schedule and may include some additional schedules with blind writes.

A blind write does not first read the value it overwrites. This can make view-equivalent schedules harder to check than the graph test.

QUICK EXAMPLE

For an exam answer, state the reads-from and final-writer conditions rather than treating view serializability as just another name for the conflict graph.

TOPIC 04

Testing a schedule for serializability

DEFINITION

The precedence-graph test decides conflict serializability by turning conflicting operation order into directed edges between transactions.

Write one node for each transaction. Compare operations from different transactions on the same item; a pair conflicts when at least one operation is a write.

For each conflict, draw an edge from the transaction whose operation happens first to the one whose operation happens later. Ignore read-read pairs.

If the graph is acyclic, a topological order gives an equivalent serial order. If it contains a cycle, the schedule is not conflict-serializable.

QUICK EXAMPLE

For S = r1(X), w1(X), r2(X), w2(Y), r1(Y), the conflict on X gives T1→T2; the conflict on Y gives T2→T1. The cycle T1→T2→T1 means S is not conflict-serializable.

WORKED EXAMPLE · SELECT A STEP

Use arrows to test a schedule

Two transactions change two marks, A and B. The order is T1 changes A, T2 reads A, T2 changes B, then T1 changes B.

OrderActionWhat it requires
1T1 changes AT1 acts before T2 on A
2T2 reads AAdd arrow T1 → T2
3T2 changes BT2 acts before T1 on B
4T1 changes BAdd arrow T2 → T1
STEP 01

Draw the first arrow

T1 changes A before T2 reads A. To keep this order, T1 must come before T2.

STEP 02

Draw the second arrow

T2 changes B before T1 changes B. To keep this order, T2 must come before T1.

STEP 03

Look for a loop

The arrows say T1 before T2 and T2 before T1. That is a cycle, so no single serial order can match it.

RESULT

A cycle in the conflict graph means this schedule is not conflict-serializable.

EXAM FOCUS

What to be ready to explain

Construct the precedence graph for a schedule, test it for a cycle, and compare conflict and view serializability.
