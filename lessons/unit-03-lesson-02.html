UNIT 03 · LESSON 02

Schema refinement, redundancy & 1NF–3NF

IN PLAIN WORDS

Schema refinement uses keys and functional dependencies to reduce repeated facts and anomalies. Normal forms guide the design, while decomposition checks protect meaning and rules.

By the end, you can:
  • Find update, insertion, and deletion anomalies
  • Follow a refinement workflow using keys and dependencies
  • Normalize relations through 1NF, 2NF, and 3NF
TOPICS IN THIS LESSON

EXPLANATION
TOPIC 01

Why redundancy causes anomalies

DEFINITION

Redundancy is storing the same fact repeatedly. An anomaly is an error or awkwardness caused by that repetition.

Update anomaly: some copies change and others do not. Insert anomaly: a fact cannot be stored without an unrelated fact. Delete anomaly: removing one row accidentally removes another fact.

Normalization uses keys and dependencies to decide which facts belong together.

QUICK EXAMPLE

If a course title appears on every enrollment row, a title correction must be applied to every student taking that course.

TOPIC 02

Schema refinement in database design

DEFINITION

Schema refinement improves a table design so each fact is stored in an appropriate place and common changes do not cause anomalies.

Start from requirements. Identify candidate keys and functional dependencies; use them to see which attributes depend on which facts.

Decompose a relation when repeated facts create update, insertion, or deletion anomalies. Select a normal form, then check losslessness and dependency preservation.

A good refinement preserves meaning. Splitting tables without checking their joins can create false combinations or make rules difficult to enforce.

QUICK EXAMPLE

For ENROLLMENT(sid,studentName,cid,courseTitle,grade), sid→studentName, cid→courseTitle, and (sid,cid)→grade. Refine into STUDENT(sid,studentName), COURSE(cid,courseTitle), and ENROLLMENT(sid,cid,grade).

TOPIC 03

First and second normal form

DEFINITION

1NF requires each cell to hold one value for its chosen domain. 2NF requires 1NF and no non-key attribute to depend on only part of a composite candidate key.

A repeating list of phone numbers in one cell violates the intended atomic layout; store one phone per row or in a separate relation.

Partial dependency matters only when a candidate key has multiple attributes. A student's name depends on sid, not on the full (sid,cid) enrollment key.

QUICK EXAMPLE

For key (sid,cid), sid → sname is a partial dependency. Put the name in STUDENT(sid,sname), not repeated in each enrollment.

TOPIC 04

Third normal form

DEFINITION

A relation is in 3NF when for every nontrivial X → A, X is a superkey or A is a prime attribute (part of some candidate key).

This condition removes problematic transitive dependencies while allowing some dependency-preserving designs that BCNF would split.

Always state the dependencies and candidate keys before claiming a normal form.

QUICK EXAMPLE

If sid → dept and dept → office, then sid → office transitively. Store department office information in DEPARTMENT rather than repeating it for every student.

WORKED EXAMPLE · SELECT A STEP

Normalize enrollment records

ENROLLMENT(sid, sname, cid, title, grade), with key (sid,cid). Rules: sid→sname, cid→title, and sid,cid→grade.

STEP 01

Check the values

If each row has one sid, one cid, and one grade, it is atomic and meets 1NF. If courses were stored as a comma-separated list, first make one course per row.

STEP 02

Remove partial dependencies

sname depends only on sid; title depends only on cid. Split those facts into STUDENT(sid,sname) and COURSE(cid,title).

STEP 03

Keep the full-key fact in enrollment

grade depends on both sid and cid, so ENROLLMENT(sid,cid,grade) keeps it. The three relations reduce repeated names and titles.

RESULT

STUDENT(sid,sname), COURSE(cid,title), and ENROLLMENT(sid,cid,grade) form a cleaner design. The key of ENROLLMENT is (sid,cid).

EXAM FOCUS

What to be ready to explain

Explain redundancy and all three anomalies. Normalize a relation step by step through 1NF, 2NF, and 3NF with the dependency removed at each step.
