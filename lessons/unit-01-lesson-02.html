UNIT 01 · LESSON 02

DBMS structure, data views & independence

IN PLAIN WORDS

DBMS structure explains how a request is checked and answered. Views show the data needed by a user; abstraction hides detail, and data independence reduces how often programs must change.

By the end, you can:
  • Name the query processor and storage manager
  • Explain external, conceptual, and internal views of data
  • Distinguish abstraction from logical and physical data independence

EXPLANATION
TOPIC 01

DBMS structure: main parts of a request

DEFINITION

DBMS structure describes the components that check a request, decide how to run it, access stored pages, enforce rules, and return the result.

The query processor parses and validates a query, the optimizer chooses a plan, and the execution engine runs that plan.

The storage manager works with data files, indexes, and the buffer pool. Transaction, authorization, integrity, and recovery components coordinate safe and permitted access.

An application does not normally fetch disk pages itself. It asks the DBMS for data; the DBMS checks the request and returns the requested result.

QUICK EXAMPLE

For “show the courses for student 21,” the query processor checks the request, the transaction and authorization components apply the rules, the storage manager finds the matching enrollment pages, and the DBMS returns only those course names.

TOPIC 02

What is data abstraction?

DEFINITION

Data abstraction means showing the useful information while hiding lower-level details that the user does not need.

A student sees course names, not the disk page number where each enrollment is stored.

Abstraction makes the same database usable by people with different needs: a student, an instructor, and a DBA can see different views.

QUICK EXAMPLE

A student portal may show name and courses. The registrar's screen may also show grades and registration dates.

TOPIC 03

View of data: the three schema levels

DEFINITION

A view of data is the version of the database a particular user or program sees. The three-schema architecture separates that view from the complete logical design and physical storage.

External level: a user-specific view, such as a student portal showing course names but not fee details.

Conceptual level: the overall logical database, including relations, attributes, relationships, and constraints.

Internal level: the physical representation, such as pages, files, indexes, and record layouts. Mappings connect the levels so a change at one level can sometimes be hidden from another.

QUICK EXAMPLE

The student portal is an external view. STUDENT and ENROLLMENT are part of the conceptual schema. A B+ tree and disk pages belong to the internal level.

TOPIC 04

Logical and physical data independence

DEFINITION

Physical independence lets storage change without changing the logical design. Logical independence lets the logical design change while user views remain stable.

Adding an index or moving a table to a new disk layout is a physical change. A well-designed DBMS can hide it from applications.

Adding a new attribute to the conceptual design is a logical change. It is independent only if existing views and applications do not need to change.

QUICK EXAMPLE

Adding an index on ENROLLMENT.sid should not require a rewrite of the student portal. Renaming a field used by the portal may require a view mapping or a program change.

WORKED EXAMPLE · SELECT A STEP

Change storage without changing the screen

A student portal shows each student's name and course. The database team adds a small lookup list so student records are found faster.

PartSimple meaningExample
External viewWhat a user seesName and course on the portal
Conceptual designWhat data the database containsStudent ID, name, and course
Internal storageHow the computer keeps the dataData pages and a lookup list
STEP 01

Look at the screen

Students see only the portal fields they need. This is their view of the data.

STEP 02

Keep the data design

The database still has the same student ID, name, and course. The meaning of the data has not changed.

STEP 03

Improve the storage

The lookup list helps the DBMS find a student faster. The portal still looks and works the same.

RESULT

The storage changed, but the screen and the data design stayed the same. This is physical data independence.

EXAM FOCUS

What to be ready to explain

Draw the three-schema architecture. Define abstraction, identify each level, and compare logical with physical data independence.
