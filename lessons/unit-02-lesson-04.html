UNIT 02 · LESSON 04

Logical design, views & SQL schema changes

IN PLAIN WORDS

Logical design turns the data model into tables. SQL can create, query, alter, and remove tables and views; a view is a saved query that can present a useful window onto data.

By the end, you can:
  • Translate an ER design into relation schemas
  • Create, query, alter, and remove tables and views
  • Explain what a view exposes and when it can be updated

EXPLANATION
TOPIC 01

Ask a question with SELECT

DEFINITION

SELECT names the output columns; FROM names the input relations; WHERE filters rows.

JOIN matches related rows from different tables. GROUP BY forms groups, then COUNT, AVG, MIN, and MAX summarize each group.

ORDER BY is needed when the answer must appear in a particular order.

QUICK EXAMPLE

SELECT cid, AVG(score) FROM Result GROUP BY cid returns one average per course.

TOPIC 02

Create and modify database structures

DEFINITION

CREATE TABLE defines columns, types, keys, and constraints. ALTER TABLE changes a table's structure.

CREATE TABLE defines columns, types, keys, and constraints. ALTER TABLE changes the structure; DROP TABLE removes the table definition and its stored rows.

INSERT adds rows, UPDATE changes values, and DELETE removes selected rows. These are data changes, not table-structure changes.

A primary-key or foreign-key constraint is part of the schema, so the DBMS can reject invalid changes.

QUICK EXAMPLE

Use ALTER TABLE Enrollment ADD COLUMN grade CHAR(2) to add a column. Use UPDATE Enrollment SET grade='A' WHERE sid=22 AND cid=301 to change a row; these commands affect different layers.

TOPIC 03

Views and updatability

DEFINITION

A view is a named SELECT statement. It is often updatable when each view row maps clearly to one base-table row.

A simple view over one table may allow updates. A grouped, aggregate, or many-table view can be ambiguous: one displayed row may represent many source rows.

Views simplify repeated queries and can limit which columns a user sees. Access permissions still decide who may read or change base data.

QUICK EXAMPLE

A fee-summary view can show sid and balance while hiding private contact details.

TOPIC 04

Additional SQL forms (extension)

DEFINITION

These useful SQL features are not named in the official Unit 2 syllabus, so treat them as optional background after the listed topics. Triggers respond to events; embedded or dynamic SQL connects queries with programs; recursive queries follow repeated relationships.

A trigger runs automatically after a specified database event. Embedded SQL is written inside another programming language; dynamic SQL is assembled while a program runs.

A recursive query repeatedly follows a relationship such as an employee-manager chain. Exact syntax varies between SQL systems.

QUICK EXAMPLE

A trigger can record an audit row after a salary update. A recursive query can follow manager_id repeatedly to find all levels above an employee.

TOPIC 05

Drop and alter tables and views

DEFINITION

ALTER changes an existing database object. DROP removes an object definition; dropping a table removes its table data as well, while dropping a view removes the saved query definition.

ALTER TABLE can add, remove, or change columns and constraints; exact syntax depends on the SQL system. CREATE VIEW defines a saved query, and DROP VIEW removes that view.

Some systems support ALTER VIEW or CREATE OR REPLACE VIEW to change a view definition. Other systems require dropping and recreating it.

RESTRICT blocks removal when dependent objects exist. CASCADE may remove dependent objects too, so use it only when those dependencies are intended to go.

QUICK EXAMPLE

Examples: ALTER TABLE Enrollment ADD COLUMN grade CHAR(2); DROP VIEW CurrentStudents; DROP TABLE OldEnrollment. DROP TABLE removes the table and its rows, so check dependencies and backups first.

Create a simple view and add a column

STUDENT has ID, Name, and Program. We want a saved list of CS student names, then we want to add a Phone column.

Choose what the view shows

The view keeps only Name and only rows where Program is CS. It acts like a saved filter.

STEP 02

See the view's result

The view shows Asha and Chen. The original STUDENT table still keeps all three rows.

STEP 03

Change the table plan

Adding a Phone column changes the table's design. Existing student rows can then be filled with phone numbers.

RESULT

A view is a saved way to look at selected table data. Altering a table changes its columns; it does not mean deleting the whole table.
