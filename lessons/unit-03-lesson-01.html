UNIT 03 · LESSON 01

Functional dependencies, closure & keys

IN PLAIN WORDS

A functional dependency is a promise about the data: once you know the values on the left, the values on the right are fixed. Closure helps test keys and consequences.

By the end, you can:
  • Read X → Y as a rule about rows
  • Compute an attribute closure
  • Use closure to find keys and check dependency sets
TOPICS IN THIS LESSON

EXPLANATION
TOPIC 01

Functional dependency

DEFINITION

X → Y means that any two rows with the same X values must also have the same Y values.

It is a rule the organization promises to follow, not just a pattern noticed in a small sample.

X is the determinant. Y is determined by X. If a student id identifies a student, sid → name.

QUICK EXAMPLE

If course id determines the department, then two rows with the same cid must have the same department.

TOPIC 02

Attribute closure

DEFINITION

X⁺ is the set of all attributes that the dependency rules can determine from X.

Start with X. Whenever the left side of a dependency is already in the set, add its right side. Repeat until no new attribute can be added.

If X⁺ contains every attribute of the relation, X is a superkey. If no smaller subset works, it is a candidate key.

QUICK EXAMPLE

Let R(A,B,C,D) have FDs A→B, B→C, and AC→D. Start A+={A}; A→B adds B; B→C adds C; now AC→D adds D. Thus A+={A,B,C,D}; A is a superkey and is a candidate key if no proper subset determines every column.

TOPIC 03

Armstrong rules and minimal cover

DEFINITION

Armstrong's reflexivity, augmentation, and transitivity rules derive dependencies that logically follow from the original rules.

Reflexivity: if Y is contained in X, then X → Y. Augmentation: if X → Y, then XZ → YZ. Transitivity: if X → Y and Y → Z, then X → Z.

A minimal (canonical) cover has one attribute on each right side, no unnecessary left-side attributes, and no redundant dependency.

QUICK EXAMPLE

If sid → name and name → email, then sid → email by transitivity.

WORKED EXAMPLE · SELECT A STEP

Find the key of a course-enrollment relation

R(Student, Course, Grade, Instructor, Room). Rules: Student,Course → Grade; Course → Instructor; Instructor → Room.

RoundNew attributesClosure
Start—Student, Course
Apply first ruleGradeStudent, Course, Grade
Apply next rulesInstructor, RoomAll five attributes
STEP 01

Begin with the proposed key

Start closure of {Student, Course}: it currently contains Student and Course.

STEP 02

Apply the matching rules

Student,Course → Grade adds Grade. Course → Instructor adds Instructor. Instructor → Room adds Room.

STEP 03

Check all attributes and minimality

The closure now contains Student, Course, Grade, Instructor, and Room, so the pair is a superkey. Neither Student alone nor Course alone determines every attribute, so the pair is a candidate key.

RESULT

{Student, Course}⁺ contains every attribute. The candidate key is {Student, Course}.

What to be ready to explain
