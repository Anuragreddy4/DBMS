UNIT 05 · LESSON 04

WAL, checkpoints, recovery & buffers

IN PLAIN WORDS

A log records concurrent changes. Write-ahead logging lets recovery redo committed work and undo incomplete work; checkpoints and the buffer manager help restore consistent pages.

By the end, you can:
  • Apply WAL and distinguish undo from redo
  • Explain checkpoints and recovery with concurrent transactions
  • Describe page pins, dirty pages, and buffer replacement

EXPLANATION
TOPIC 01

Log-based recovery, atomicity, and WAL

DEFINITION

A log records transaction actions so the DBMS can recover after a failure. WAL requires the log record to reach stable storage before the changed data page is written.

A log record identifies its transaction and update. Depending on the recovery method it contains the old value, the new value, or enough information to reconstruct them.

Undo restores the before-image of an uncommitted update. Redo repeats an update that belongs to committed work. WAL requires the relevant log record to reach stable storage before its changed data page is written.

A system can use force or no-force and steal or no-steal policies. These choices determine which updates may need redo or undo after a crash; log-based recovery handles the chosen policy.

QUICK EXAMPLE

Before flushing a page that now contains balance=80, the log record describing the change must already be durable. If the update was uncommitted at crash time, undo restores the old balance; if it committed but the page was not flushed, redo restores 80.

TOPIC 02

Checkpoint and ARIES

DEFINITION

A checkpoint records recovery information so restart can begin near recent work. ARIES recovers in Analysis, Redo, and Undo phases.

Analysis finds active transactions and dirty pages. Redo repeats the history needed to restore pages. Undo rolls back incomplete transactions and records compensation log records.

A checkpoint can be fuzzy: transactions may continue while it is written.

QUICK EXAMPLE

The transaction table and dirty-page table help recovery identify which work and pages need attention.

TOPIC 03

Buffer manager

DEFINITION

The buffer manager keeps disk pages in memory while queries use them.

Pin means a page is currently in use and cannot be replaced. Unpin says the operation is done with it. A dirty bit means the page has changes not yet flushed to disk.

LRU and clock are replacement strategies for choosing an unpinned page to evict. Flushing writes a page back to storage, subject to WAL.

QUICK EXAMPLE

A query pins a page, reads rows, then unpins it. If it changed a row, the page is dirty until flushed.

TOPIC 04

Recovery with concurrent transactions

DEFINITION

Concurrent recovery tracks several transactions whose log records may be interleaved, then restores committed work and removes incomplete work after a crash.

Each log record includes a transaction identifier and a log sequence number. A checkpoint helps recovery identify active transactions and pages that may need repair.

Recovery distinguishes committed transactions (winners) from incomplete transactions (losers). It redoes required history so pages are consistent, then undoes loser transactions; ARIES records compensation log records during undo.

The log order matters even when transactions overlap. Recovery follows the log rather than assuming each transaction occupied one uninterrupted block.

QUICK EXAMPLE

T1 updates page P and commits. T2 updates page Q but has no commit record when power fails. On restart, recovery ensures T1’s update is present and undoes T2’s incomplete update, even if their log records were interleaved.

WORKED EXAMPLE · SELECT A STEP

Recover after a crash

T1 transferred funds and committed. T2 started an update but did not commit before the crash. T1's log is durable; one data page was not flushed.

STEP 01

Analysis

Recovery scans the log and identifies T1 as committed and T2 as incomplete. It also identifies pages that may contain unflushed changes.

STEP 02

Redo

Recovery reapplies T1's logged update if the page lacks it, ensuring the committed transfer is present.

STEP 03

Undo

Recovery reverses T2's incomplete update using the before-image or undo information, then records that action in the log.

RESULT

The recovered database includes all committed work and none of T2's partial work. WAL makes the needed undo and redo information available.

EXAM FOCUS

What to be ready to explain

Explain WAL, log records, atomicity and durability, undo/redo, checkpoints, recovery with concurrent transactions, and buffer management.
